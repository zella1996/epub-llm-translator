# 日文 EPUB 适配：分 session 开发与验收计划

## 1. 文档用途与当前状态

本文是后续开发 session 的任务划分和验收契约。

- 编写基线：2026-09-15，分支 `codex/japanese-book-support`。原始提交历史保存在本机私有归档；后续 session 应记录自己的实际起点。
- 问题来源：[日文适配阻塞清单](../.japanese-test-books/JAPANESE_ADAPTATION_BLOCKERS.md)。该文件及真实书籍只在本机，未随仓库分发；本文保留可独立执行的需求与验收边界。
- 阶段范围：S0–S10。S0–S7 的实际完成状态和证据见进度文档；S8 起改用原生 EPUB 完成剩余验收。
- 执行约定：默认一个 session 执行一个步骤；用户明确指定组合步骤时可合并。完成本步骤后交接，下一步骤由后续 session 接续。

## 2. 最终目标和范围

“达到类似英文目前的效果”分成三个必须分别证明的层面：

1. **功能完整**：日文 EPUB 可以 inspect、dry-run、单段预览、按章翻译、整书遍历与写回；默认段译／句意卡流程和 `reading-v1` 阅读辅助流程均有语言正确的处理路径；缓存、恢复、索引绑定、输出校验可用。
2. **原书完整**：原正文、ruby、原注释、导航、链接、CSS、spine 顺序及翻页方向保持；新增内容通过对应 EPUBCheck 基线与目标阅读器检查。
3. **阅读价值**：中文段译准确自然；辅助能解释日文的真实理解障碍；歧义不猜定；与英文一样可以连续阅读、定位原句、打开辅助并返回。需真实模型和人工内容抽查证明。

S3–S9 采用的能力边界是日文本地难度跳过关闭、日文句法分析关闭。S10 经合成测试和三书
离线零误跳审计后，默认启用独立的固定短应答安全门控；它不使用英文词数或形态素分析，且可
显式关闭。日文句法仍为 `off`，不能据此宣称费用、速度或难度选择率与英文相同。GiNZA／日文
Stanza 是另立任务的后续优化，不是首版完成条件。

## 3. 架构原则与模块边界

### 3.1 语言差异集中，共用编排复用

建议把源语言策略与“源语言到目标语言的任务提示词”区分开。最终文件布局由 S1 决定，但下列职责边界必须成立：

| 层 | 负责 | 不应负责 |
| --- | --- | --- |
| 源语言策略／注册表 | 语言标签规范化、支持列表、分句、门控能力、语言专属校验与版本 | ZIP、DOM 写回、HTTP 客户端 |
| 翻译任务模块 | 英译中／日译中独立任务说明、语言专属例子、提示词身份 | 供应商传输、EPUB 解析 |
| 共用模型编排 | 阶段调度、重试、JSON schema、索引完整性、取消、预算、缓存 | 散落的日文／英文启发式 |
| EPUB 层 | 安全解析、语义文本提取、快照、注释渲染、归档与链接保护 | 根据文本猜语言、英文难度判断 |
| CLI／调优配置 | 将书籍语言、模型设置、用户参数解析成可审计的有效配置 | 静默套用不匹配的语言或句法模型 |

建议能力接口包括 `source_code`、`split(text)`、`gate(text, ...)`、`validate_translation(...)`、句法支持信息，以及 splitter/gate/validator 的版本身份。具体命名不是硬性要求；以单一职责、无循环依赖和可测试性为准。

共用任务组合类型应对语言中立，英文、日文分别实现语言行为；避免让日文继承英文语义类，再逐项禁用其规则。保持英文既有公开入口兼容，减少无关历史 profile 的重构。

### 3.2 文本、DOM、缓存三个独立契约

- **模型文本**：ruby 取基础文字，忽略 `rt/rp`；保持正文字符和内部空白，明确排除内容的处理方式。
- **原 DOM**：读取不改写；完整保留 ruby、原节点及属性。注释只通过生成节点和受保护的定位链接加入。
- **快照**：文本快照前后使用同一提取算法；结构快照独立比较原节点、属性及层次，排除工具生成部分。文本相同不能代替结构相同。
- **缓存**：包括规范化源语言、任务／prompt 身份、splitter/gate/validator 版本及有效句法身份；两个 pipeline 的缓存、冻结清单和 replay 都要核查。英文旧缓存是否仍兼容必须给出明确结论。

## 5. 阶段提交边界

每个步骤达到本步骤的验收边界后，必须形成独立、可定位的 Git 提交边界，再开始下一步骤。一个步骤可以跨多个 session；只有实际完成全部验收的 session 负责关闭该步骤。

关闭步骤时按以下顺序执行：

1. 重新运行本步骤要求的测试和检查，保存实际命令、结果及本机证据路径。检查完整 diff，确认提交内容只属于当前步骤，并排除真实书籍、凭据、模型 trace、含私有正文的报告和生成译本。
2. 更新 `docs/japanese-adaptation-progress.md`，将状态改为“完成”，写明改动、验收、未执行项和接口／缓存／prompt 版本。此时“交付提交”可暂写“待本次提交”。
3. 提交当前步骤的实现、测试、fixture 和必要文档，提交信息必须包含步骤编号，例如 `feat(japanese): complete S2 EPUB extraction`。基线或纯文档步骤可使用合适的 `test:` 或 `docs:` 类型。
4. 取得交付提交哈希后，再把实际哈希写入进度文档，并单独提交交接记录，例如 `docs: record S2 acceptance`。提交不能可靠地在自身内容中记录自身最终哈希，因此不得用占位哈希冒充交付标识。
5. 确认 `git status` 中没有遗留的当前步骤改动；启动下一步骤的 session 时，以交付提交和交接记录提交共同作为前置边界。启动前已存在的无关改动可以保留，但必须在交接中逐项注明。

步骤尚未满足验收边界时，状态保持“进行中”或“阻塞”，后续 session 继续同一步。确需保存中间成果时可以创建带步骤编号的 checkpoint 提交，并在进度文档中明确尚缺哪些验收；checkpoint 不授权进入下一步骤，也不能标记为“完成”。

提交边界的验收标准：

- 当前步骤的所有验收项都有通过证据，或未执行项已使状态保持为未完成。
- 交付提交不混入下一步骤的实现；下一步骤不为当前步骤“顺手实现”。
- 交付提交可由后续 session 独立检出和验证，交接记录能指向准确提交哈希。
- 工作区内属于当前步骤的改动已经提交；本机忽略目录中的证据路径仍可从交接记录找到。

## 6. 各步骤任务书

### S0 — 固定基线和验收材料

**实现目标**：让后续 session 能区分旧问题、新问题和环境缺失。

**实现方式**：

1. 读取仓库约定、当前状态文档及本计划；记录提交、工作区已有改动、Python 环境、EPUBCheck／阅读器版本。
2. 跑现有英文测试，记录通过／失败／跳过及原因。仅用纯文本结论交接，不复制凭据或整本正文。
3. 构造可提交的日文 fixture：`ja`/`ja-JP`/大小写变体、嵌套语言覆盖、不同 ruby 结构、连续日文标点、竖排 CSS、RTL spine。
4. 重测三本真实书的 EPUBCheck、ZIP、链接集合、章节与段落分布；记录源文件哈希和适合单章验收的候选章号。《草枕》的原始资源、spine、导航、ruby、writing mode、翻页方向和 Media Overlay 形成结构基线。
5. 为入口拒绝、日文分句、ruby 基础文本等问题建立最小失败用例。失败测试在修复前应可单独运行，或明确标记已知未实现行为，避免无说明地留下全套红灯。

**验收边界**：基线、最小失败证据、fixture 和命令均可重现；真实源错误与实现缺陷分开。此步不解除语言限制、不调用真实模型。

**交接**：基线报告、fixture 路径、失败用例命令、工具缺失项及选章依据。

### S1 — 建立语言策略与配置边界

**实现目标**：后续语言差异有统一入口；英文行为不因架构调整改变。

**实现方式**：

1. 在 `translator/languages.py` 周边建立中立的公共协议／组合类型和语言注册机制，确定与源语言策略的依赖方向。
2. 明确标签策略：`ja`/`ja-JP`/大小写变体归一到 `ja`；保留原始元数据。未知语言报清晰错误；缺失语言延续现有兼容行为并记录。多个 `dc:language` 的选择或歧义规则要显式定义并测试，不能“任意一个支持就按英文处理”。
3. 列出有效配置如何由书籍语言、语言任务、模型调优和 CLI 参数组合。日文自动选日译中任务；显式不匹配配置在模型调用前报错。
4. 定义 cache/profile/prompt/splitter/gate/validator/syntax 身份的组合位置，覆盖正常生成与冻结结果读取。

**验收边界**：协议和配置单元测试通过；英文既有 profile 行为兼容；日文与英文身份可区分。此步可只建立能力边界，不要求日文正文链路已可运行。

**交接**：接口说明、标签决策表、缓存版本策略、后续应调用的唯一解析入口。

### S2 — 正文提取与 ruby 保真

**实现目标**：支持日文书籍入口，提取正确基础正文，并保持源 DOM。

**实现方式**：

1. 修改 `EpubBook._load_package()`，通过 S1 注册表设置规范化源语言属性，仅允许已实现语言能力的书籍。
2. 修改 `_inside_excluded_content()`：最近有效 `xml:lang/lang` 相对于书籍源语言判定；保留原有脚注、诗歌等排除规则。
3. 明确内嵌外语的粒度：段落级排除与段内元素级排除分开测试。若排除段内片段，文本抽取与快照须一致，保留相邻 tail；禁止用整段的语言判断冒充内嵌片段支持。
4. 将 `_text_without_generated()` 的语义抽取和结构保存分开：跳过 `rt/rp` 显示文本，保留基础文字、节点 tail 和相邻内容，不修改 ruby DOM。
5. 覆盖熟字训、分组 ruby、连续 ruby、有／无 `rp`、`rb`、嵌套行内标记；核查基础正文与结构快照的各处调用。

**验收边界**：三本书均能返回非零正文；自建 fixture 精确断言预期正文和外语排除；读取前后 DOM／资源哈希不变。此步不声称句界、译文或注释布局正确。

**交接**：三书段落统计、ruby 测试矩阵、语言筛选粒度与快照规则；单列《草枕》的结构金标准清单。

### S3 — 日文精确分句和处理范围

**实现目标**：句子索引绑定正确，日文不会被英文规则误跳过。

**实现方式**：

1. 在日文策略内实现分句：`。！？`、连续标点、`」』）】` 等闭合符；覆盖无终止符会话、引号内句界、引用后接“と言った”等叙述的边界规则。
2. 覆盖省略号、破折号、小数、拉丁缩写及其紧邻日文的情况。明确分句规则，不为得到边界而改写原字符。
3. 每个句子是原字符串的精确连续切片；索引连续且稳定。明确句间空白是否排除，内部空白保持；测试按偏移验证不漏正文、不重叠。
4. 日文关闭所有英文局部门控：整段跳过、短会话、短句辅助抑制、按英文单词数保留句意卡、英文候选补选。不影响用户显式选择／跳过范围。
5. 日文句法身份为 `off`；显式要求英文 Stanza/spaCy 时在传输前报错，不创建英文分析器。

**验收边界**：边界矩阵通过；含 Latin 名称的短日文段也不被按少量英文词跳过；两个 pipeline 的索引和处理数量一致。仅证明处理范围正确，不证明模型难度判断准确。

**交接**：分句版本、边界例子、逐项移除英文门控影响的位置及测试。

### S4 — 独立日译中任务与输出校验

**实现目标**：日文模型输入、提示词和输出契约完整，复用通用结构校验。

**实现方式**：

1. 为默认段译／句意卡流程和 `reading-v1` 分别提供日文任务说明；复用各自既有 JSON 结构和编排。
2. 明确敬语施受关系、主语省略、指代、句末语气、拟声拟态词、汉字同形异义、专名及 ruby 处理；亲属称谓不套用英文词保留规则。专名采用可执行的一致策略并测试。
3. 日文校验放到语言策略。通用层继续检查索引覆盖、重复、类型、字段范围、非空内容、长度及精确来源绑定；英文小写词／英文代词规则只作用于英文任务。
4. 为日文定义可检查的错误与留给模型／人工复核的语义边界，避免用“含假名即错误”误拒专名，也避免把关闭英文校验当作日文质量证明。
5. 所有 draft/review/repair、quality replay 和用户提示中的语言说明一起检查。日文冻结语法输入必须带适配身份，首版只接受 off。

**验收边界**：用自建例子的冻结模型响应验证两个 pipeline 的成功、缺失索引、额外字段、错误原句、保留专名、歧义、修复路径；日文提示词无英文专属行为规则，英文原有契约通过回归。

**交接**：版本化日文 prompt/profile、校验职责表、离线样例结果及需要真实模型验证的假设。

### S5 — CLI、缓存、恢复、估算与预览贯通

**实现目标**：用户从正常入口即可选择正确语言，不依赖临时脚本绕过主流程。

**实现方式**：

1. 在 `cli.py` 与 `translator.py` 接通 S1–S4，覆盖 inspect、dry-run、默认 preview/translate，以及 reading-v1 translate、冻结缓存／manifest 预览。
2. 语言从 EPUB 元数据解析一次并向下传递；纯文本实验和 replay 从显式输入／冻结身份解析，不能根据假名出现与否猜测。
3. 缓存和冻结结果校验绑定源语言、分句与规则版本；验证首次生成、同配置缓存命中、变更配置失效、失败后恢复、错误语言拒绝。
4. 修正日文 token 估算，避免沿用英文字符除以四。记录估算方法、提示词和 review/repair 预留；它是运行预算依据，不是供应商计费保证。保留现有实际 token 截止机制。
5. 输出有效语言、gate、syntax 和任务身份，便于验收；确保 dry-run 零传输，配置错误在传输前退出。

**验收边界**：两个 pipeline 使用假模型的端到端测试通过，索引与数量吻合；三书 inspect 和指定范围 dry-run 可运行；真实模型调用次数为零。预览文件包含明确 PREVIEW 标记，原文件不覆盖。

**交接**：两个 pipeline 可执行命令、估算说明、缓存／manifest/replay 兼容性结论、单章验收具体章号建议。

### S6 — 整书写回、ruby 定位与排版兼容

**实现目标**：离线覆盖整书写回，证明语言适配不破坏阅读结构。

**实现方式**：

1. 对三本真实书使用明确标注为离线测试内容的假模型／冻结结果，遍历目标正文并写回；输出不能标为真实翻译成品。执行顺序为《人間失格》主流程、《草枕》结构金标准、住野よる边缘样本。
2. 核查 phrase 定位：只匹配模型可见基础正文；`rt/rp` 中相同读音不算可链接位置；跨多个 ruby／行内节点的短语不能直接破坏 DOM。首版可回退到原句辅助定位，需明确测试回退行为。
3. 新增注释继承所在正文 writing mode；评估逻辑方向边距／边框与目标阅读器兼容性，保留横排效果。检查块级插入是否合法，不能假设 EPUB 2 支持所有 EPUB 3 标签和属性。
4. 以《草枕》作为 EPUB 结构金标准：写回前后比较所有受影响章节的基础正文与结构快照、资源哈希、原链接集合、导航、ruby 计数与属性、spine 翻页方向、writing mode、CSS、字体、非 ASCII 内部路径及 Media Overlay。生成节点按明确规则排除后比较原结构。《人間失格》继续承担横排主流程与内容基线，不以其较简单结构替代《草枕》的结构结论。
5. 《人間失格》和《草枕》输出要求 EPUBCheck 零错误、零警告，其中《草枕》是规范结构验收的判定样本；住野よる边缘样本通过 `--allow-invalid-source` 接受基线，比较归一化输入／输出 findings 与链接问题差集。

**验收边界**：三本整书离线输出 ZIP 完整；《草枕》的结构金标准清单逐项通过；其他样本无原结构／资源退化，且无新增 EPUBCheck/link findings。仅完成结构兼容，原生 EPUB 的真实模型结论由 S8 提供，阅读器视觉结论由 S9 提供。

**交接**：本机输出路径、验证命令与集合差异报告、ruby 定位回退说明、待目检页面坐标。

### S7 — 《人間失格》单章真实模型验收

**实现目标**：在已确定范围和预算内验证日译中阅读价值。

**实现方式**：

1. 从 S0/S5 交接选择一个有正文的 spine 章，记录章号、段落数和输入哈希。模型固定为用户确认的 `glm-5.3-flash`；从 S5 交接取得与日文任务兼容的有效 provider/profile，并在运行前核对其模型名、日文 task/prompt identity、思考参数和传输参数。当前仓库的已验证直连 provider 为 `zhipu-glm53`；任何模型变更都需要新的用户指示。
2. 遵循可用的 EPUB translation runner 工作流。先 inspect 与精确配置 dry-run，固定 token 上限、缓存、日志与输出路径，再运行本章。单章授权不扩展为整书调用。
3. 用该章缓存或冻结结果生成单段预览并检查辅助返回链接，避免为同一验收无理由重复模型调用。若需变更 prompt 后重跑，记录失效原因和剩余／新预算。
4. 抽查至少 12 个段落；章节不足则全检。覆盖 ruby、对话、省略主语、敬语／语气、长句及专名；章内缺少的现象由自建定向样例补足，不能扩发其他真实章节。
5. 对每个抽查项记录：原文对齐、事实／否定／指代、中文自然度、辅助是否必要且有帮助、是否加入无依据解释。问题按严重度分级，并回到对应开发步骤修复。

**验收边界**：所选章所有应处理段落生成或由有效缓存覆盖；无静默漏段、未恢复失败或新增结构错误；抽查无事实反转、误定指代、虚构情节等严重错误，无妨碍理解的译文问题。轻微措辞问题逐项记录。运行退出码为零只证明运行结束。

若只有一个 pipeline 做了真实运行，报告明确该范围；另一个 pipeline 的离线证据不能冒充真实质量证据。需要两种产品模式都宣称同等质量时，应在同章和明确预算内分别验收。

**交接**：实际处理／缓存／失败计数、模型和供应商身份、估算与实际 usage、可得费用、EPUBCheck、输出及抽查报告；正文材料留在本机忽略目录。

**证据边界**：本步骤使用的《人間失格》由 XHTML 经 Calibre 转换。S7 只证明日译中模型质量、缓存恢复和转换样本写回；不能作为原生 EPUB 或 Kindle 兼容性证据。

### S8 — 《草枕》原生 EPUB 有界端到端验收

**实现目标**：用官方原生 EPUB 样本生成真实日译中输出，为 Kindle 实机测试提供可信输入。

**实现方式**：

1. 固定 `.japanese-test-books/kusamakura-w3c.epub` 的 SHA-256、官方发布来源、许可、EPUBCheck、spine 和结构基线；确认使用的是 W3C/IDPF 发布文件而非重新打包版本。
2. 通过正式 inspect 选择一个有代表性的正文 spine 章节，覆盖竖排、ruby 和正常段落结构；记录章号、段落数及 dry-run 估算。新书范围的真实模型调用需要用户另行明确授权；未授权时只完成预检并保持 S8 未完成。
3. 获得授权后，使用 `reading-v1`、`glm-5.3-flash`、`glm53flash-japanese-reading` 和 `zhipu-glm53` 翻译该章节；不扩展到整书，不向模型发送商业样本。输出、缓存、manifest、trace 和报告放入 `.epub-llm-translator/japanese-s8/`。
4. 验证全部目标段落由生成或有效缓存覆盖，并完成缓存重建、EPUBCheck、ZIP、链接、正文、ruby、导航、spine、CSS、字体、非 ASCII 路径和 Media Overlay 差异检查。原生复杂资源的结论必须基于《草枕》真实输出，不以 S6 占位结果代替。
5. 人工抽查至少 12 段，覆盖 ruby、古典／文学表达、长句、省略、语气和专名；记录严重、妨碍理解和轻微问题。语言年代造成的代表性限制单列，不把《草枕》当作现代日语质量的唯一基准。
6. S8 的“全部目标段落”仍按 S3 的 `off-v1` 日文门控定义。不得在本章已生成缓存的中途按字符数缩小目标集合；短段落仍可作为 JSON、修复路径和句末语气的回归刺激。日文短文本节流在 S10 以独立、版本化策略验收，不能用未审计的字符阈值改写 S8 结论。

**验收边界**：选定章节全部处理且可从缓存重建；输出 EPUBCheck 为零错误零警告，无新增链接或原生结构／资源退化；人工抽查无严重或妨碍理解问题；形成一个明确标识的 Kindle 待测 EPUB。只有离线占位输出或未经授权的 dry-run 不能关闭 S8。

**交接**：源哈希和官方来源、章号与段落范围、模型配置、估算与实际 usage、输出/cache/manifest 路径、结构差异报告、人工抽查及 Kindle 待测文件。

### S9 — Kindle 实机视觉与交互验收

**实现目标**：新增辅助在目标阅读器实际可读、可定位、可往返。

**实现方式**：

1. 当前目标阅读器为 Kindle 上的 KOReader。由用户以同一方式导入原始《草枕》和 S9 试读版，记录 Kindle 型号、固件、KOReader 版本、导入方式和实际打开的文件哈希。若另测原生 Kindle/Send to Kindle，单独记录 Amazon 转换结果，不与 KOReader 结论混用。
2. 以《草枕》为主验收：检查竖排方向、ruby、段译、句译卡、辅助列表、行距、边距、换列、链接标记、RTL 翻页、目录导航、正文到辅助跳转及阅读器历史返回。至少覆盖一个长段、一个含 ruby 段和章节边界。
3. 区分工具退化和平台限制：原版和输出都有的 KOReader/设备表现单列，只有输出相对原版新增的问题归因于适配器。Amazon 转换限制仅在实际使用 Send to Kindle 时判定。
4. Apple Books 或 Calibre 可用于定位差异，但不能替代 Kindle 上 KOReader 的主验收。《人間失格》S7 输出只作横排回归参考；横排日文的生成样式还须做离线回归，不能由竖排《草枕》实机结论代替。住野商业样本仅在用户愿意时用离线占位输出检查边缘布局，不影响《草枕》主结论。
5. 截图、页面坐标和含正文证据保存在 `.epub-llm-translator/japanese-s9/`，不得提交或公开。发现适配器问题时增加自动回归、修复并重新导入目检。

**验收边界**：Kindle 上 KOReader 中，相对同渠道原版没有新增截断、重叠、方向错误、异常换页、导航失效或无法返回；分割线异常已消除，译注入口易于点按。KOReader/源书问题单列。未完成真实设备复测时保持“待验收”，结构测试或桌面阅读器不能替代；本阶段不声称原生 Kindle/Send to Kindle 已通过。

**交接**：Kindle 型号／固件、KOReader 版本／导入方式、原版与输出对照矩阵、截图或本机证据路径、平台限制、已修复或待修复的具体页面。

### S10 — 英文回归与发布交接

**实现目标**：完成可审计的首版交付，并让下一次维护能定位语言边界。

**实现方式**：

1. 运行完整自动化测试及环境支持的 EPUBCheck／Calibre 集成测试；与 S0 比较失败及跳过。验证英文缺省语言、旧 profile、门控、输出格式和缓存兼容性。
2. 汇总 S2–S9 证据，覆盖两种 pipeline 的能力矩阵和三个真实样本；原生 EPUB 与 Kindle 结论必须引用《草枕》S8/S9 证据，不把《人間失格》转换样本或未执行项目标为通过。
3. 增加日文专用的轻量短文本门控，避免未来正常流程对高置信简单应答逐段调用模型。该规则属于日文语言策略，不复用英文 15-word 计数，不引入形态素分析依赖，也不得只凭字符数跳过：至少拒绝问句、省略、否定、条件／转折、未完句、指代／指示、专名／ruby 和诗歌。先用不含真实书稿的合成例句锁定正反例，再对三本离线样本输出“拟跳过坐标和计数”并人工审计；只有零误跳才可成为日文默认值，否则保持显式 opt-in。
4. 为该门控增加独立版本身份和报告字段，dry-run 必须分别列出模型段落与日文短文本跳过段落，并明确“跳过即无译文兜底”。门控选择语义与生成结果缓存身份应分开：已有且 prompt/schema/source identity 相同的生成结果仍可复用，但旧 manifest 不得冒充新门控运行；迁移行为须有缓存命中与零调用回归测试。
5. 更新用户文档：支持的源语言、自动选择方式、日文 gate/syntax 身份、命令示例、预算差异、缓存迁移及源错误处理。
6. 检查 diff：仅包含适配代码、自建 fixture 和文档；无书籍、凭据、trace 正文或无关工作区改动。

**验收边界**：本计划最终清单全部满足，或明确列出阻塞并保持“未完成”。此步骤不自动授权发布、合并或整书真实翻译。

**交接**：变更摘要、测试与验收报告入口、已知限制、可复现命令及最终提交标识。
