## 当前调优目标与阶段门槛（2026-08-27 更新）

保留本标题供旧链接定位；旧轮次的逐项规则已归档。当前目标是准确、完整、可读且尽量
遵循英文信息展开的中文，不把逐词照搬、唯一译法或字段数量作为目标。
继续使用 v6 实验基线；完整 prompt 与历史结果见 [literal baseline](literal-meaning-baseline.md)。

先判断“句意相对段译的价值”，再决定如何改模型输入、译文数据流或界面。
不能用五句调参结果、六卡抽样或 EPUB 技术通过，替代未见样例及读者验收。

## 1. 零调用：对已有输出做配对审计

输入为本地已有缓存和 trace，不重新跑 EPUB，不调用 fast 或 quality。
对全部 15 张卡找回对应 fast `translations[index]`，同时保留整段译文作为对照。
最终缓存只有拼接段译，不能靠中文标点重新分句假装恢复准确索引；缺失 fast trace 时标缺失。

审计表至少包含：段／句索引、fast 句译、quality 原始 meaning、最终是否保留、
重复／定位收益／顺序收益／纠错／冲突、原文证据、需要的上下文及待判断项。
原文和完整输出仅放在 Git 忽略的 `.epub-llm-translator/model-tests/` 下。

另将所有原句的选卡状态列出，检查漏选，不只看成品中可见的 15 张卡。
将 fast 未选、本地补选、quality 改判、后处理抑制四种情况分开。

**出口：**全部卡片可配对或有明确缺失说明；冲突和疑似漏选有源句位置。
精确重复率或相似度只用于筛查，不替代语义重复、定位价值或学习效果判断。

## 2. 一次只选择一种实验

先根据审计选择一项，不顺次自动执行全表：

| 实验 | 唯一主要变量 | 固定项与边界 |
| --- | --- | --- |
| 两阶段保留规则 | fast 保留规则与 quality v6 对齐 | 原文、其他 prompt 与模型参数固定；不能同时加上下文 |
| 同段上下文 | quality user 增加当前段落必要非候选句 | 同一候选、同一 Stanza、同一 system；仍不发相邻段落／整章 |
| 句意 prompt | system 中一个已观察失败对应的规则 | user、难度协议、Stanza 与 effort 固定 |
| reasoning | 同一冻结 prompt 的 effort | 两档使用同一输入、输出上限与协议；单独预核可用参数 |
| 展示价值 | 段译视图与段译＋卡片视图 | 使用已有同批译文，先做离线阅读；不夹带模型质量变化 |

同段上下文实验须预先明确比较目标：只改变输入证据，不同时让模型改段译或新增卡片字段。
字段名、索引、上下文角色和最大输入范围先通过本地测试；输入不足时保留不确定性。
fast 专项可用纯文本 fast 请求，不需要 EPUB；句意专项仍只调用 quality。

通用协议遵守 [纯文本验证规范](model-prompt-text-testing.md)。新增／修订 prompt 默认英文，
历史中文基线不批量翻译。外发文本、endpoint、模型、请求数、实际 payload、输出上限、
输入预留、总 token／费用上限和停止策略必须在调用前明确并取得用户授权。
历史实验预算不是未来实验的余额或授权。

**出口：**一个假设、一个对照、冻结样本与参数、预先写定的判定规则和本轮预算。
不满足这些条件时仅做本地准备。

## 3. 样本与评分分开设计

**生成质量：**候选与对照均采用相同冻结难度协议。预定难例须返回完整非空 meaning，
不能以改判 fluent 绕过任务。覆盖长插入、否定／条件／比较、语境词义／习语、
省略、指代、专名／亲属边界和确定程度。保持原始失败记录。

**筛选质量：**另用正常难度复核及后处理，包含困难与简单句；人工标签在调用前确定。
分别报告候选召回、quality 标签、最终卡片漏选和过选，不把少卡等同于质量好。

**段句一致性：**并排检查 fast 句译、拼接段译与 meaning。重点看人物／亲属、否定范围、
比较对象和语气；一张卡更好不能掩盖段译仍错。上下文是从原文获得的证据，fast 译文不能
作为事实权威。

**读者增量：**使用已冻结译文做展示比较，观察辅助能否解除卡点、让阅读继续，以及
提示与跳转是否造成负担。只收集自愿提供的阅读反馈，不要求读者解释结构，不安排
新句迁移或复述测试；不以看过同一内容后更快证明能力提升。设计参照
[教材评审](reading-design-review-2026-08-28.md)，不照搬课堂练习。
本节未见样例、评分与重复轮次均由开发侧用于检查模型输出，不是给读者的作业。

**出口：**生成、筛选、一致性、阅读价值各自有结果；未测试项标“未测试”。
五句调参回归集不能再作为未见验收集；未见样例和重复轮次须另行确定并计入授权。

## 4. 当前验收口径

这是本项目建议的下一轮口径，不回写历史分数，也不是厂商或教材的统一标准。

- **协议：**全部预定索引恰好一次；冻结难例 meaning 覆盖完整；无截断、无静默降级。
  额外字段单独记录为契约偏差；当前业务解析器并未实现严格的额外键拒绝，不能把
  “解析成功”报告成“字段契约全部通过”。
- **语义底线：**不接受关键事实捏造／遗漏、人物关系错误、否定／条件／因果反转、
  实质性语气改变或误导的习语直译。重大错误不能由平均分抵消。
- **阅读可用：**逐项判“可用”“可用，有轻微瑕疵”“需修正”。局部生硬或自然中文所需的
  语序调整不自动失败；长篇讲解取代翻译视为失败。
- **保留边界：**姓名及附带称谓逐字复制；亲属词只在翻译会引入未声明关系时保留。
  阅读是否可用与保留规则是否合规分开报告；不把系统性保留失败称为完全可用。
- **质量诊断：**四项 0–2 分（语义完整、信息展开、中文可读、证据／保留边界）可用于
  定位问题，不把旧版 7/8 自动当作本轮唯一门槛。
- **设计增量：**保留第二份独立翻译或增加提示，须指出它解决的具体障碍。仅措辞变化
  不算增量；纯定位收益可以支持双视图，但不能证明需要双重生成。

试运行全部预定难例应有可评结果，且均至少达到“可用，有轻微瑕疵”，无重大错误和
系统性保留失败，才能称“本轮样例可用”。若声称优于基线，还需配对指出收益与回退。
稳定性、泛化及默认发布另定样本和重复轮次；不从单轮推导“最佳方案”。

性能比较仅在任务覆盖与质量均达标后进行。记录实际 input、completion、reasoning、
缓存用量和 API 耗时；reasoning 已包含在 completion 时不重复相加。
本地解析、EPUB 流程和重试耗时分别统计；API 未返回费用时不能记为免费。

## 5. 停止与实现边界

新研发轮次默认 transport/schema 自动重试均为 0；预先授权的重复测量不属于失败重试。
认证、参数拒绝、超时、截断、非法 JSON 或预算不足时保存结果并停止当前阶段，
不悄悄换 effort、扩大上限或多调一次。历史整章的 schema retries=1 是该次运行设置，
不改写成当时没有配置重试。

本次没有新增一个可复用的纯文本 CLI；当前仓库的 `quality-replay` 仍绑定历史 replay
契约。若后续实现通用文本入口，须以 mock 验证无 EPUB／生产缓存访问，并保留来源与
hash；不要覆盖旧 trace 或跳过指纹校验来假装是同一实验。

将来若实现共享句译或 quality 修订段译，须先扩展现有测试，覆盖索引完整、未修订句
保留、版本／缓存隔离、段句一致性和渲染。仅在另行授权阅读／集成验收时生成 EPUB。
不改变原文、普通单向链接、输入文件不覆盖等既有约束；未获用户接受不切换默认。

交付每轮的输入与版本、原始输出、全部失败、评分与争议、真实用量和明确结论：
“本轮可用／需修正／执行未完成”。付费结果与个人正文只保存在本地忽略目录。
